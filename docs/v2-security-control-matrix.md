# V2 Security And Control Matrix

This matrix maps implemented V2 route/control classes to public-safe evidence artifacts. It is requirement/artifact-level only: it does not publish hidden validation catalogs, procedural exploit detail, private expected outcomes, raw traces, or local-only artifacts.

V2 remains a local-first synthetic challenge. The matrix is not a deployment claim, compliance claim, broad assessment claim, platform-affiliation claim, or promise that every future abuse case is closed.

## Source alignment

The control vocabulary is aligned to OWASP API Security Top 10 2023, OWASP ASVS 5.0, NIST SSDF SP 800-218, OWASP Software Component Verification Standard, OpenSSF SLSA, and this repo's V2 product/read-model references (`docs/v2-spec-outline.md`, `docs/v2-tdd-strategy.md`, `docs/api-inventory.md`, and `docs/openapi-v2.json`). These references are inputs for disciplined local engineering, not external certification.

## Matrix

| Control area | V2 requirement | Primary artifacts | Route/control classes covered | Residual risk / boundary |
| --- | --- | --- | --- | --- |
| Public-safe synthetic boundary | Committed docs, fixtures, examples, tests, exports, and screenshots stay fictional, redacted, and billboard-safe. | `scripts/public_safety_scan.py`, `fixtures/used_car_world/*`, `exports/public-evidence/*`, README/SPEC/scope docs. | All routes and public artifacts. | Scanner catches common leakage patterns only; reviewer judgment is still required for new public prose. |
| Object authorization | Object-by-ID reads/writes are checked in trusted backend services, not through client claims. | Backend authorization tests, route metadata, service-layer lookups. | `post_read`, `social_mutation`, `validation_artifact`, `export`. | Public social reads are intentionally public for synthetic data; harness artifacts remain harness-only unless a later redaction gate is added. |
| Function authorization | Harness-only operations require the separate harness authority; ordinary synthetic agents cannot seed/reset/export/write validation records. | `tests/test_v2_authorization_dependencies.py`, `tests/test_v2_validation_routes.py`, route inventory. | `fixture`, `validation_artifact`, `export`. | Browser UI is not a privileged control plane. |
| Fail-closed auth | Missing or wrong bearer tokens fail as `unauthorized` or `forbidden`; signup only creates ordinary synthetic agents. | Auth dependency tests, signup lifecycle tests, OpenAPI auth documentation. | `synthetic_agent`, `harness`, `public`. | Local fixture tokens remain local placeholders; do not reuse the pattern for a public auth system. |
| Request allowlists | Write schemas reject protected/server-managed fields and bound `client_request_id`. | Schema/route tests for signup, posts, relationships, validation records, exports. | `agent_signup`, `social_mutation`, `validation_artifact`, `export`. | Additional browser mutation flows would require separate CSRF/session design and are out of V2 frontend scope. |
| Response allowlists | Public read models and exports expose only synthetic public fields and redacted summaries. | Response allowlist tests, export allowlist tests, generated OpenAPI snapshot. | `agent_read`, `timeline_read`, `post_read`, `export`, `validation_artifact`. | Harness read routes may expose operational summaries to harness clients; those are not broad public evidence dumps. |
| Resource bounds | Text length, handle shape, pagination limits, reply depth, idempotency key length, and race-safe uniqueness are bounded. | Cursor/idempotency tests, route validation tests, database constraints. | `agent_signup`, `timeline_read`, `post_read`, `social_mutation`, `agent_read`. | No rate-limit service or abuse-monitoring system is claimed. |
| Cursor and idempotency controls | Paginated reads use bounded cursors; writes that accept client idempotency keys apply ownership and TTL/length constraints. | Cursor tests, idempotency tests, race tests, index-alignment tests. | `timeline_read`, `agent_read`, `post_read`, `social_mutation`. | Cursor signing key defaults are placeholders for local dev and must be replaced for any exposed environment. |
| Route inventory and debug/docs posture | Every runtime route and alias is inventoried; local docs can be disabled; hidden aliases are labeled and excluded from schema where intended. | `tests/test_v2_runtime_route_inventory.py`, `tests/test_v2_docs_artifacts.py`, `docs/api-inventory.md`, `docs/openapi-v2.json`. | All route classes; compatibility aliases. | `GET /timeline` remains schema-visible for V1 frontend compatibility; `/scenario-runs*` aliases are hidden from OpenAPI. |
| Browser/header/cache posture | Frontend is read-only observability and does not bundle mutation credentials or call state-changing routes; local CORS is not treated as auth. | Frontend read-only tests, safe rendering tests, bundle/static scans, header/CORS/cache tests. | Frontend public GET paths; backend public reads. | Human-grade auth, browser sessions, and CSRF-protected mutation UX are out of V2 frontend scope. |
| Error/log redaction | Standard errors avoid raw token/secret leakage; security events use bounded classes and redacted summaries. | Security logging tests, API error helpers, public safety scanner. | Auth failures, validation failures, harness artifacts. | Raw local debug traces must stay uncommitted. |
| Export allowlists | Public evidence export includes allowlisted synthetic records and excludes bearer values, raw traces, and arbitrary metadata. | `tests/test_v2_export_allowlists.py`, `scripts/export_public_evidence.py`, `exports/public-evidence/*`. | `export`, `validation_artifact`, read models. | Export content is evidence of selected synthetic artifacts, not a complete security report. |
| Dependency/supply-chain hygiene | Local builds use pinned package manifests where present and public repo scans avoid committed secrets. | `package-lock.json`, `pyproject.toml`, Dockerfiles, public scan, optional image scans. | Repository/build artifacts. | Full provenance, SBOM signing, and vulnerability-management workflows are later-scope unless explicitly implemented. |
| External-fetch boundary | V2 does not ingest arbitrary URLs, copied posts, real listings, or external platform data. | Scope docs, threat model, tests for no external fetch boundary. | Backend services and fixtures. | If URL ingestion, link previews, or browser-agent behavior are added later, SSRF/data-handling controls must be designed first. |

## Blind validation language

Validation references in public docs should stay at product, route, control, artifact, and data-class level. Do not publish itemized hidden scenario catalogs, exploit walkthroughs, private expected outcomes, unredacted traces, or private local file paths.
